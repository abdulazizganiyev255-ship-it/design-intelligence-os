# UX psychology as testable prompts, not decorative laws

Each heuristic is a possible explanation, not proof. Cite https://www.nngroup.com/articles/ten-usability-heuristics/ and https://lawsofux.com/ for concepts, then test observable tasks.

| Lens | Diagnostic question | What to measure | Anti-overreach |
|---|---|---|---|
| Recognition vs recall | Can user identify action without remembering a secret gesture? | wrong taps, first-action success | Icon alone is not always bad; context matters |
| Hick choice load | Are simultaneous choices actually relevant? | selection time/error in task | Don't arbitrarily cap options to a magic number |
| Fitts target | Is the important action accessible at actual thumb and device scale? | missed taps, touch size | Not all large buttons improve hierarchy |
| Gestalt grouping | Are related data and actions visually grouped? | misread relationships | Proximity is a heuristic, not automatic proof |
| Error prevention | Can an irreversible action be cancelled? | error recovery time | Confirmation on every harmless action harms flow |
| Progressive disclosure | Is advanced filtering appropriately secondary? | time to common task | Hiding essential settings is not simplification |
| Cognitive load | Is the screen asking for multiple independent judgments? | task completion/comments | Less content isn't always better |
| Aesthetic usability effect | Does polish affect confidence? | measured perceived ease vs task success | Beauty cannot replace functional truth |
| Feedback | Do users know whether operation saved? | success-state comprehension | Fake optimistic UI is unacceptable for finance |
| Trust/financial truth | Can user tell session demo from live account? | comprehension quiz | A small DEMO tag alone may be insufficient |

Required skill output: exact screenshot/flow location, observed fact, hypothesis, falsifiable test, proposed correction and counterexample. Avoid invented neuroscience or universal conversion percentages.
