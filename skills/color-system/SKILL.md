# color-system — Design Intelligence OS v0.3

**Stage:** S05. **Mode:** supervised ChatGPT role workflow; not an autonomous agent.

## Objective
Build semantic colors and verified contrast after the art direction is chosen, never by palette-first guesswork.

## Inputs
Owner-approved concept, roles/states, brand boundaries, light/dark surfaces, evidence of meaning.

## Procedure
1. Separate primitive swatches and semantic names: surface, text, action, border, focus, status, chart.
2. Test normal/large text and non-text affordances for appropriate WCAG contrast in real component context.
3. Verify income/expense/negative/error/success meaning is not conveyed solely by hue.
4. Check dark/light state equivalents, disabled/selected/hover/focus and chart series distinction.
5. Ask Creative for craft and UX for semantics; only then approve component token handoff.

## Outputs
semantic color role table, theme map, contrast test matrix and fallback colors.

## Acceptance / Quality gate
Colors are functional and pass documented contrast goals; no invented bank trends, no color-only signal and Owner visual direction unchanged.

## Sources and caution
https://www.w3.org/TR/WCAG22/ ; https://github.com/design-tokens/community-group

Link and extract principles with source provenance; do not import external code/skill text or claim tests that have not run. Every Board use logs four role positions with documented dissent.
